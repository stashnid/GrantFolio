# GrantFolio

GrantFolio — асистент для підготовки бізнесу до грантового фінансування. Локальна тестова версія підтримує реєстрацію/вхід, профіль бізнесу, приватні проєкти, опис клієнтів і плану реалізації, бюджет, перевірку заповненості та завантаження робочої чернетки TXT. Дані зберігаються в PostgreSQL.

Пілотна програма — «Власна справа», вибір користувача. Відкритий раунд і чинну офіційну форму ще не підтверджено; картка веде до першоджерела. Перевірка заповненості не визначає відповідність програмі. ШІ у застосунок ще не інтегровано: Gemini Flash-Lite перевірено окремим API-запитом, провайдер для початкової інтеграції; Claude наразі не потрібен. HTTPS deployment і публічний URL ще відсутні.

[Повне бачення продукту](docs/product-vision.md) описує цільові можливості; реалізований обсяг наведено вище.

## Локальний запуск

Потрібні Node.js 24, npm та запущений Docker з Compose. Команди виконуються з кореня репозиторію. Auth Emulator створює тільки локальні тестові акаунти; PostgreSQL використовує локальний Docker volume.

```sh
cp .env.example .env
npm ci
docker compose up -d --build
npm run migrate
npm run dev
```

Відкрийте http://localhost:5173. Зареєструйтеся з тестовим email і паролем, заповніть профіль і відкрийте «Мої плани»: створіть чернетку, заповніть опис проєкту, клієнтів, канали продажу, план реалізації та очікувані результати. Збережіть опис, додайте витрати й збережіть бюджет. Перевірте список збережених даних і завантажте робочу чернетку TXT. Експорт містить збережену версію та позначає відсутні поля; це матеріал для підготовки, не офіційна заявка. Ціна вводиться у гривнях з не більше ніж двома знаками після коми; сервер розраховує підсумок у цілих копійках. Оновіть сторінку або вийдіть і увійдіть знову. Якщо бюджет змінився в іншій вкладці, форма зберігає ваші незаписані зміни для копіювання до завантаження актуальної версії. `.env` містить лише локальні налаштування; не додавайте до Git справжні секрети. Emulator і база доступні лише через loopback хоста. Для зупинки сервісів: `docker compose down`. Volume з профілями зберігається.

```sh
npm run typecheck
npm run build
npm test
```

Інтеграційний тест потребує запущених emulator та PostgreSQL, виконаної міграції й `.env`; він створює два тестові акаунти та перевіряє ізоляцію профілів і чернеток, некоректні токени, арифметичні межі, конкурентні зміни та повтори команд бюджету. Акаунти emulator тимчасові, профілі у volume зберігаються.

## Production image

`Dockerfile` збирає frontend і API в одному образі. Для майбутнього production build необхідно передати `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` як build arguments; це публічна конфігурація Firebase, не секрети. Runtime потребує `FIREBASE_PROJECT_ID`, `DATABASE_URL` та налаштованих Application Default Credentials. Emulator заборонений у production. Міграцію потрібно виконувати окремим процесом з цього образу командою `npm run migrate:prod` перед запуском; готового deployment або cloud resources наразі немає. Потрібні HTTPS, Firebase email/password, реальні домени та окрема перевірка перед публічним використанням.
