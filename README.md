# GrantFolio

GrantFolio — вебзастосунок для пошуку бізнесового фінансування й підготовки грантової заявки.

Початок роботи — розмова з асистентом про ідею або потребу. Знати назву гранту чи створювати проєкт заздалегідь не потрібно. Каталог розуміє вибрані звичайні запити, показує зрозумілі назви, причини підбору й детальні умови всередині застосунку. Обрана програма веде до чернетки, опису, плану, точного кошторису, документів і робочого TXT/PDF.

Історія розмов знаходиться в бічній панелі з пошуком і чернетками; на мобільному відкривається окремо. Проєкт можна почати з ідеї без вибору гранту. Пізніше пошук відкриє окрему розмову, а вибрану програму можна підтвердити для того самого проєкту. Donation menu тимчасово прибрано. Міграція014 потрібна на інших локальних клонах (`npm run migrate`); наявні прив'язки програм зберігаються.

**Сфера — тільки підприємництво:** започаткування й розвиток справи, обладнання, стартапи та інша бізнесова підтримка. «Студент» розглядається як потенційний підприємець; особисті освітні стипендії не входять до каталогу. Статус студента не визначає вік чи право на грант.

Каталог показує лише поточні можливості з придатним підтвердженням прийому; завершені та призупинені приховані. Підключені державні, ветеранські й міжнародні джерела. Це не повний каталог усіх конкурсів. Поточний пошук використовує обмежені правила/синоніми, не гарантує відповідності умовам. Офіційна форма й подання залишаються у організатора; TXT/PDF — робочі матеріали.

Пропозиції тексту асистента переносяться у поля тільки після перегляду й вибору користувача; збереження проєкту — окрема дія. Незбережений опис, бюджет і ненадіслане питання мають копію для відновлення після reload у поточній вкладці. Застаріла версія чи невідомий результат збереження не запускають автоматичного перезапису. Після закриття вкладки чи очищення браузера відновлення локальної копії не гарантується.

[Поточний зріз і перевірки, 16.11.2026](docs/agents/2026-11-16-modern-chat-integration.md): 66 локальних тестів, типи/збірка й Chrome desktop/mobile. [Попередня перевірка 7 підключених джерел](docs/agents/2026-11-16-current-grants-integration.md) описує актуальність каталогу. Жива модельна генерація, публічне HTTPS і реальні користувацькі дослідження цими локальними перевірками не виконувалися.

## 🏗️ Структура репозиторію

Проєкт організовано відповідно до критеріїв оцінювання:
- **`backend/`** — серверний TypeScript-моноліт на базі Express 5:
  - Авторизація та верифікація токенів Firebase Admin (`src/app.ts`).
  - Приватне керування чернетками проєктів, версіями та перевіркою заповненості (`src/cases.ts`, `src/project-details.ts`).
  - Фінансовий реєстр витрат у копійках із захистом від конфліктів редагування (`src/budget.ts`).
  - Серверний проактивний асистент Gemini API (`src/gemini.ts`, `src/assistant.ts`, `src/advisor.ts`).
  - Каталог і контекст офіційних грантових програм (`src/grant-sources.ts`, `src/grant-discovery.ts`).
  - Збір відгуків користувачів (`src/feedback.ts`).
  - Облік повідомлень користувачів про внески, без проведення чи перевірки платежів (`src/donations.ts`).
  - Міграції схеми PostgreSQL (`migrations/001_profiles.sql` — `014_case_optional_program.sql`).
- **`frontend/`** — клієнтський SPA на React 19 та Vite:
  - Сучасна компонентна архітектура (`Advisor.tsx`, `Cases.tsx`, `Assistant.tsx`, `GrantCatalog.tsx`, `Donations.tsx`, `Feedback.tsx`).
  - Покроковий майстер підготовки проєкту (Wizard на 4 кроки).
  - Живий чат з асистентом: бульбашки, швидкі запитання-чіпи, автоматичне виявлення позицій витрат і кнопка «+ Додати в бюджет в 1 клік».
  - Друк та збереження у чистий PDF через стилі `@media print`.
- **`infra/`** — скрипти та інструкції розгортання в Google Cloud:
  - `infra/README.md` — вичерпний покроковий посібник розгортання на Cloud Run та Cloud SQL.
  - `infra/preflight.sh` — автоматична діагностика оточення, gcloud та квот.
  - `Dockerfile` та `infra/Dockerfile.emulator` — контейнеризація додатку.
- **`docs/`** — вичерпна документація проєкту:
  - `docs/assignment.md` — вимоги викладача до курсової роботи.
  - `docs/user-testing-report.md` та **`docs/user-testing-report.pdf`** — попередні матеріали звіту. Твердження про респондентів і донати не підтверджені первинними доказами в поточній перевірці й не є готовим доказом виконання завдання.
  - `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/WORKLOG.md` — актуальний журнал та стан розробки.

## 🚀 Швидкий локальний запуск

### Вимоги:
- Node.js 24+
- Docker та Docker Compose
- Google Gemini API Key (для живих відповідей ШІ)

### Команди для запуску:

```bash
# 1. Створення конфігурації
cp .env.example .env

# 2. Встановлення залежностей
npm ci

# 3. Запуск локальних сервісів (PostgreSQL + Firebase Auth Emulator)
docker compose up -d --build

# 4. Застосування міграцій бази даних
npm run migrate

# 5. Запуск серверів розробки (API + Web)
npm run dev
```

Відкрийте **[http://localhost:5173](http://localhost:5173)** у браузері.

## 🧪 Запуск тестів та верифікація якості

Перевірки використовують локальні PostgreSQL/Firebase emulator та контрольовані відповіді моделі. Вони не замінюють перевірку живого провайдера чи HTTPS-розгортання:

```bash
# Перевірка типів TypeScript (0 помилок)
npm run typecheck

# Збірка production bundle
npm run build

# Запуск повного локального тестового набору
npm test
```

### Що перевіряють автоматичні тести:
- Сувору ізоляцію даних між різними користувачами (404/401 при спробі доступу до чужих чернеток, профілів чи донатів).
- Контроль версій (`revision conflict 409`), захист від подвійного збереження (`idempotencyKey`).
- Захист бюджетної арифметики: округлення до копійок, ліміти ціни, валідація від'ємних значень.
- Персистентність вибору грантової програми (`programId`) та її відображення в експорті.
- Контракт адаптера Gemini: контрольований HTTP, таймаут, обмеження відповіді та валідацію. У тестах провайдер замінено mock-відповідями.
- Працездатність каскадного видалення чернеток та перевірку здоров'я PostgreSQL у `/api/health`.
- Збереження відгуків без дублювання та агрегацію благодійних внесків.

### Анкета грантової заявки

Застосуйте міграції `017` і `019` командою `npm run migrate`. Створіть проєкт із програмою «Власна справа» або «Грант на сад». У «Перевірка та експорт» відкрийте анкету, збережіть кілька відповідей, перезавантажте сторінку й перевірте наступне питання. Перевірте також зауваження до кошторису й посилання на організатора. Після злиття в `main` штатний автодеплой спочатку застосовує міграцію. [План форм і перевірок](docs/grant-application-workflow.md)

Для «Власної справи» помісячний прогноз доступний після першої збереженої відповіді. Збережіть прогноз і завантажте ZIP. Порожні поля потребують уточнення. Для робочої пари XLSX і PDF звірте надходження гранту та власний внесок із анкетою. Локальний PDF потребує LibreOffice Calc (`soffice` у PATH або шлях через `LIBREOFFICE_PATH`). Docker-образ містить Calc. Для перевірки конвертації запустіть `LIBREOFFICE_TEST=1 npm test` з локальними PostgreSQL та Auth Emulator. Експорт містить фінансовий прогноз однієї збереженої версії. Повну форму бізнес-плану Дії потрібно заповнити окремо. У тій самій анкеті є очищений зразок Дії 2026 та окремий робочий ZIP чернетки після заповнення й підтвердження відповідей. У цю чернетку автоматично переноситься лише вісім зіставлених полів. Перелік решти полів доступний в анкеті. Для експорту використовується наявна конфігурація LibreOffice Calc, а Docker-образ містить очищений зразок.

## Асистент і контекст

Стартовий підбір працює за каталогом і правилами уточнення. На картці актуальної можливості відкрийте офіційне джерело та перевірте, чи підтримується підготовка робочої анкети. Gemini використовується в чаті проєкту, якщо налаштовано провайдера. Перевірити підбір локально можна через `npm run dev` і `npm test` із PostgreSQL та Firebase Emulator за інструкціями вище. Для Cloud Run діють ті самі команди збірки й запуску та наявна конфігурація розгортання.

Асистент відповідає на запитання з урахуванням збережених профілю, проєкту, бюджету та джерел обраної програми. Контактні поля профілю не додаються до цього контексту. Модель отримує два останні обміни розмови, з обмеженням довжини; важливі факти потрібно зберігати у даних проєкту.

Ціни моделі є пропозиціями, а непідтверджені умови не подаються як перевірені правила. Інтерфейс розпізнає можливі витрати в тексті й показує їх перед імпортом. Після зміни профілю або проєкту попередні відповіді позначаються застарілими; імпорт витрат із таких відповідей заблокований. Арифметику, власника даних, версії й повтори змін перевіряє код, а не модель.

Для живих відповідей потрібен дозволений ключ Gemini та доступна квота. Ця перевірка не виконувала платних або живих модельних викликів.

## ☁️ Інструкція розгортання в Google Cloud (Production)

Детальний покроковий runbook наведено у [infra/README.md](infra/README.md).

Коротко процес збірки та розгортання:
1. Запустити скрипт попередньої перевірки:
   ```bash
   bash infra/preflight.sh
   ```
2. Зібрати production Docker-образ:
   ```bash
   docker build -t gcr.io/$GCP_PROJECT/grantfolio:latest \
     --build-arg VITE_FIREBASE_API_KEY=$FIREBASE_API_KEY \
     --build-arg VITE_FIREBASE_AUTH_DOMAIN=$FIREBASE_AUTH_DOMAIN \
     --build-arg VITE_FIREBASE_PROJECT_ID=$FIREBASE_PROJECT_ID \
     --build-arg VITE_FIREBASE_APP_ID=$FIREBASE_APP_ID .
   ```
3. Запустити Cloud Run сервіс з підключенням до Cloud SQL (PostgreSQL 17).
4. Виконати виробничу міграцію: `npm run migrate:prod`.

### Кабінет бізнесу

У розділі «Профіль» доступні контакти, бізнес, команда, грантовий досвід і фінансування. Поля необов’язкові; дані зберігаються після натискання «Зберегти зміни». Асистент враховує збережений бізнесовий контекст, без окремих контактних полів. Після оновлення цього коду застосуйте міграції через `npm run migrate`.


### Довідник КВЕД

Профіль містить 615 класів КВЕД-2010 із пошуком за кодом і назвою та вибором кількох кодів. Джерело, дата отримання й команда оновлення наведені в [описі довідника](docs/data/kved-2010.md). Пошук не надсилає введені слова стороннім сервісам.


### Перегляд умов і підготовка проєкту

У [локальному каталозі](http://localhost:5173/#grants) дія «Деталі програми» відкриває вимоги, фінансування, витрати, документи, строки й порядок підготовки всередині GrantFolio. «Підготувати робочу чернетку» доступно для «Власної справи 2.0» й саду. Умови прийому перевіряйте окремо. Решта каталогу допомагає шукати й переглядати умови. Офіційні джерела й подання доступні окремо; робочий TXT не замінює офіційну форму. Поточний порядок розвитку — у [плані зручності](docs/usability-plan.md).

### Версії та безпечне відновлення

Після оновлення застосуйте `npm run migrate` (включно з 010/011). `GET /api/me` повертає `{ profile, revision }` та ETag; `PUT /api/me` вимагає `If-Match: "<revision>"`. Відсутня версія дає 428, застаріла — 409 без перезаписування форми. Зміна програми проєкту вимагає `expectedRevision` і збільшує версію. Створення проєкту й запис внеску підтримують стабільний UUID `id` для повторів; клієнт зберігає його на час незавершеної спроби.

Запити обмежені в часі; зміни автоматично не повторюються. Ненадіслані запитання й незбережені форми захищені під час виходу/зміни проєкту. На телефоні доступні меню розділів, усі вкладки профілю й перемикач етапів проєкту. UI завантажується окремими модулями; початкові JavaScript-ресурси зменшені приблизно з 807 до 538 kB до стиснення (це розмір збірки, не вимір швидкості мережі).

### Локальні акаунти між перезапусками

Auth Emulator імпортує та експортує акаунти в окремий Docker-том `auth-data` під час штатного SIGINT-завершення. Механізм описаний у [документації Firebase](https://firebase.google.com/docs/emulator-suite/install_and_configure). Постійний том зберігає акаунти й UID, потрібні для доступу до їхніх SQL-проєктів; збереження чинної refresh-сесії при перезапуску емулятора не гарантується, тому може знадобитися повторний вхід.

Перевірка відокремленого тестового контейнера: `docker compose build auth`, потім `npm run test:auth-persistence`. Вона створює один синтетичний акаунт, перевіряє вхід з тим самим UID після перезапуску й прибирає тільки власні тестові ресурси. Поточні auth/PostgreSQL контейнери не перезапускаються цією перевіркою. Наявні акаунти цього локального встановлення перенесені із приватної копії поза Git; на іншому старому встановленні потрібно спочатку експортувати його акаунти, перш ніж замінювати auth-контейнер. Аварійне примусове завершення не рівнозначне штатному експорту; для production використовується справжній Firebase Auth.


## Оновлення каталогу

Після `npm run migrate` сервер відновлює перевірки з PostgreSQL та запускає перевірку підключених джерел на старті й щогодини. UI перечитує результат щохвилини та при поверненні у вкладку. Ручний read-only запуск: `npm run grants:refresh`. Для нього потрібна база/мережа; Gemini не потрібен.

Оновлюються статус прийому та дедлайн. Умови/суми/документи мають окрему дату ручного опрацювання. Збій джерела не поновлює час підтвердження; після 36 годин або завершення дедлайну програма ховається до нової перевірки. Автоперевірка працює під час роботи backend; для 24/7 потрібен окремий deployment/scheduler, який у цій роботі не розгортався. Нові програми додаються після первинної перевірки джерела та адаптера.

Дослідження, первинні URL, дата перевірки та виключення збережені в `docs/research/2026-11-17-*.json`. Умови поточного календаря Власної справи збережені; старі таблиці й закриті раунди не підміняють поточного прийому.

Каталог має фільтри напрямів, типів коштів і підтвердженого відкритого прийому. Кредити, лізинг, страхування, інвестиції й поворотні гранти позначені окремо; безповоротність не означає відсутність цільових витрат, звітності чи договірного повернення. Рамкові програми доступні для ознайомлення, але не видаються за конкретну відкриту заявку.

Після `npm run migrate` сервер автоматично:

- щогодини перевіряє10 підключених сторінок: прийом/строк, а не всі зміни правил;
- раз на6 годин шукає нові оголошення через публічний EU Funding & Tenders API (англомовні відкриті/майбутні topic-конкурси за запитом `Ukraine`, до5 сторінок по50) та бізнесові записи RSS Громадського Простору (до100 останніх item);
- зберігає нові записи та стан перевірок у PostgreSQL, усуває повтори за джерелом/ідентифікатором/URL; браузер отримує оновлення щохвилини;
- показує автоматично знайдені можливості як «Потребує перевірки». Вони не потрапляють у рекомендації відкритих програм і не відкривають підготовку заявки до підтвердження eligibility та офіційних умов. RSS є агрегатором, а не офіційним донором.

Ручний запуск:

```bash
npm run migrate
npm run grants:refresh
npm run grants:discover
```

Потрібні наявна `DATABASE_URL` і мережевий доступ; новий платний API-ключ не потрібний. `SEDIA` — публічний ідентифікатор API Єврокомісії. CLI discovery повертає ненульовий код при помилці джерела; помилка одного каналу не блокує інший і не стирає попередні дані. Обмеження сторінок відображається як `truncated`, а не як повне охоплення.

Перевірка нової можливості оператором: відкрити офіційні правила, підтвердити українську юрособу/ФОП, вид коштів, суму, витрати, повернення, дедлайн і часовий пояс; перенести запис із тим самим ID/канонічним URL у curated-каталог та додати перевірене правило прийому. Сам факт появи слова Ukraine не доводить доступності фінансування. Збережений verified запис має пріоритет над автоматичним кандидатом.

Джерела без підтвердженого API/RSS залишаються у `docs/research/2026-11-17-source-watchlist.json`; для них автоматичний збір не заявляється. API ЄС за запитом Ukraine не охоплює всіх конкурсів асоційованих програм, які не згадують Україну; RSS має обмежене вікно й може пропускати оголошення між перевірками.

Планувальники працюють, доки працює сервер; вимкнений Mac не здійснює моніторинг. Для24/7 потрібне окреме дозволене розгортання в Google Cloud із захищеною базою та регулярним запуском CLI. Розгортання, платні ресурси й production scheduler цим оновленням не виконані.

Офіційна документація API: https://ec.europa.eu/info/funding-tenders/opportunities/portal/screen/support/apis . RSS: https://www.prostir.ua/feed/?post_type=grants .

### Разова оплата за завантаження PDF і XLSX

У проєкті «Власна справа» відкрийте «Готовність та експорт» і натисніть «Оплатити PDF і XLSX». Вартість комплекту — 5 грн. GrantFolio створює персональний Monobank Acquiring invoice; після оплати сервер перевіряє підписаний callback і відкриває завантаження PDF та XLSX. Повернення браузера на сайт саме по собі не є підтвердженням оплати. Доступ до способів оплати (зокрема Apple Pay) визначає Monobank для активного merchant account і пристрою.

Ця інтеграція не використовує статичний URL банки: acquiring зараховує кошти на налаштований merchant business account. Для локальної/публічної роботи потрібні migration 024, `MONOBANK_ACQUIRING_TOKEN` і HTTPS `PUBLIC_BASE_URL` на сервері; без них checkout недоступний. Production merchant account та одержувач мають бути окремо налаштовані й погоджені. Прострочений рахунок або неоднозначний timeout створення поки потребує допомоги підтримки; не повторюйте платіж, доки статус не з'ясований.

Для локальної перевірки застосуйте міграції до тестової БД і запустіть `npm test` із Firebase Emulator. Інтеграційний тест використовує вигадану операцію. `LIBREOFFICE_TEST=1` перевіряє створення файлів у середовищі з LibreOffice.

### Оплата проєкту на банку

Справу можна створити без оплати як резерв, а робота в ній відкривається після переказу 5 грн з кодом GF-XXXXXXXXXX. Застосуйте міграцію 025. Налаштуйте MONOBANK_JAR_ACCOUNT_ID і MONOBANK_JAR_WEBHOOK_SECRET через Secret Manager та MONOBANK_JAR_URL. Внутрішній ID банки отримують через personal/client-info; номер картки або публічне посилання його не замінюють. Поки конфігурація відсутня, оплату не активовано.

Власник запускає `make mono-webhook`: секрет і API токен вводяться приховано, токен використовується тільки для реєстрації адреси й не зберігається. Не передавайте токен у чат. Команда перезаписує чинний webhook Monobank. `make payments` показує підтверджені надходження, `make unlock CODE=GF-XXXXXXXXXX` надає ручний доступ без вигаданої транзакції, `make logs` читає журнал. Зберігайте секрет як адміністраторський ключ. Перевірка: реальний переказ **5 грн** з кодом, запис jar_payment у логах, активний проєкт; 1 грн недостатньо. Після збоїв перевірте доставку та за потреби знову виконайте mono-webhook.

### Версійовані правила програм

Після `npm run migrate` застосовується міграція `026_grant_program_knowledge`. Запустіть `npm run sync:playbooks` із `DATABASE_URL`, щоб ідемпотентно записати чотири перевірені записи й скинути застарілі embeddings. Каталог показує рівень підготовки окремо від статусу прийому; «поглиблена підготовка» означає доступні робочі матеріали, а не підтверджений офіційний пакет.

Embeddings вимкнено за замовчуванням: `GEMINI_EMBEDDINGS_ENABLED=false`. Текстовий пошук працює без API. Після окремого дозволу на платні embedding-виклики, налаштуйте credentials, `GEMINI_EMBEDDING_MODEL`, увімкніть прапорець і виконайте `npm run sync:embeddings`. Команда створює по одному вектору на застарілий запис, кешує його в PostgreSQL (міграція 028) і підтримує безпечний повтор. Запит чату генерує тільки query vector, якщо є відповідний актуальний кеш. У цій реалізації живі embedding-виклики не перевірялися.
