# Архітектура першого релізу GrantFolio в Google Cloud

Пропозиція на погодження від 17 листопада 2026 року. Мета — публічний HTTPS-сайт із реєстрацією та підтвердженою роботою для щонайменше 30 одночасно активних користувачів.

## Сервіси та дані

- Один публічний Cloud Run service віддає React і обслуговує Express API на тому самому HTTPS-домені `run.app`. Початкова конфігурація — 1 vCPU, 512 MiB, `min=0`, `max=3`, `concurrency=16`. Це стартові параметри для вимірювання. Cold start перевіряємо окремо. Один теплий інстанс розглядаємо за результатами тесту і перевірки витрат. [Cloud Run concurrency](https://docs.cloud.google.com/run/docs/about-concurrency)
- Firebase Authentication обслуговує реєстрацію, вхід і відновлення пароля. Express перевіряє ID token і обмежує приватні операції перевіреним UID. Спільну роботу різних вебінстансів забезпечує Cloud SQL for PostgreSQL 17. Пропонуємо однозонний інстанс з автоматичними резервними копіями в тому самому регіоні, попередньо `europe-west1`. Підключення через інтеграцію Cloud SQL без дозволених зовнішніх мереж. Поточний пул має максимум 5 з’єднань на вебінстанс, тож початковий розрахунок для трьох вебінстансів — 15, із додатковим запасом для job, міграцій і переходу між ревізіями. Точний тариф і ліміти БД визначимо за кошторисом і вимірюваннями. [Cloud SQL із Cloud Run](https://docs.cloud.google.com/sql/docs/postgres/connect-run) · [Firebase ID tokens](https://firebase.google.com/docs/auth/admin/verify-id-tokens)
- Cloud Scheduler щогодини запускає окремий Cloud Run Job для оновлення грантів. Переносимо наявний CLI в job, вимикаємо таймер у production web і захищаємо запуски від накладання через PostgreSQL. Каталог читає останні збережені перевірки з БД. [Заплановані Cloud Run Jobs](https://docs.cloud.google.com/run/docs/execute/jobs-on-schedule)
- Artifact Registry зберігає образ. Окремий Cloud Run Job застосовує міграції один раз перед випуском вебревізії з того самого digest. Secret Manager зберігає пароль БД та ключ Gemini, якщо асистент увімкнено. Cloud Logging і Monitoring показують затримки, помилки, використання ресурсів і стан оновлення каталогу. [Секрети Cloud Run](https://docs.cloud.google.com/run/docs/configuring/services/secrets)
- Для асистента зберігаємо наявний серверний адаптер Gemini Flash-Lite. Доступ до живої генерації залежить від підтвердженої квоти й покриття витрат. Для запуску з асистентом обмежуємо генерацію за UID і спільною квотою проєкту, зберігаємо доступ до каталогу, профілю й проєктів при відмові провайдера. [Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)

## Критерії приймання

30 різних тестових акаунтів працюють одночасно 15 хвилин по HTTPS. Прогін охоплює хвилю входів, перегляд каталогу, читання й збереження профілів, проєктів і бюджетів та TXT-експорт. Для основного API запропоновано p95 до 1 секунди та менше 1% неочікуваних помилок і таймаутів. Усі підтверджені збереження мають читатися повторно, доступ до чужих даних має відхилятися. Окремо перевіряємо старт із нуля, роботу під час оновлення каталогу і пікову хвилю. Заміряємо CPU, пам’ять, SQL-з’єднання та HTTP 429/5xx. Живу генерацію вимірюємо окремо в межах дозволеної квоти, із затримками та відмовами провайдера. Гарантія для 30 одночасних генерацій потребує окремої перевірки квоти й реального тесту.
