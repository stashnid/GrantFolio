# Оплата проєкту через банку

- Координатор: Codex Sol; backend і frontend: Terra (`jar_backend`, `jar_ui`).
- Гілка: `codex/automatic-monobank-payment`, база `8182d00`; інтегровано main після свіжого fetch (merge `55dad24`).
- Завдання: 5 грн на банку за окремий проєкт; безкоштовні каталог та загальний чат. Створення справи резервує назву; робота в ній потребує підтвердженого платежу.
- Шляхи: `monobank-jar.ts`, migration025, `cases.ts`, обидва export routers, `Cases`, `ProjectPayment`, `GrantApplication`, Makefile, operator helper, документація.
- PostgreSQL зберігає код GF + 10 hex символів, платіжну операцію за унікальним ID та окремий ручний доступ. Код відшукується у comment/description після нормалізації кирилиці; перевіряються ID банки, UAH, hold=false, час і 500 копійок. Один платіж не розблоковує декілька кодів. Сервер обмежує приватні project endpoints незалежно від UI. Раніше підтверджені оплати збережені.
- GET вебхука 200; невідомі події 200; помилка PostgreSQL 503 для повторної доставки замість тихої втрати транзакції. Неавторизовані секрети 404. Не зберігати особистий API token. Секрет URL дає доступ до summary/unlock і потребує захисту як адмін-ключ; Cloud Run request logs можуть містити URL, доступ до них обмежити.
- Схема доставки банком описана в https://api.monobank.ua/docs/index.html. Факт доставки саме для цільової банки не підтверджений. Технічна реалізація не підтверджує схвалення сервісу банком.
- Для активації потрібні MONOBANK_JAR_ACCOUNT_ID (внутрішній id з client-info, НЕ номер картки й НЕ sendId), MONOBANK_JAR_WEBHOOK_SECRET (випадкові 32+ символи) у Cloud Run/Secret Manager. Тоді власник запускає make mono-webhook, вводить секрет і персональний токен приховано. Повторний виклик замінює попередню адресу вебхука банку.
- Команди: make payments (summary), make unlock CODE=GF-XXXXXXXXXX (окремий ручний доступ без фальшивої оплати), make logs. Для демонстрації з цим тарифом потрібні 5 грн: 1 грн не відкриє доступ.
- Блокер релізу: gcloud повернув Reauthentication failed; потрібен повторний вхід власника. До налаштування конфігурації сторінка не повинна запрошувати робити переказ.

## Перевірки та межі
Typecheck, production Vite build, diff-check PASS. Чотири цільові тести webhook (включно з реальною тимчасовою схемою PostgreSQL) перевіряють дублі, суму, коди і owner isolation. Незалежне Terra review: повний GET власної збереженої справи залишається дозволеним для збереження доступу до раніше внесених даних; створення нової роботи, чат у справі, анкета, бюджет, експорт вимагають оплати. Legacy entitlement уніфіковано на рівні проєкту. Загальний регресійний набір ще потребує оновлення платіжних fixtures під нову модель перед злиттям. Саме існування PR не активує webhook.
