## Реалізація і перевірки

Створено owner-scoped API чернеток, budget команду з SQL row lock, optimistic revision, повтором за ключем і незмінною історією revisions. Валідація обмежує цілі кількості та копійки; сервер відхиляє переповнення safe integer. Міграції 001 і 002 застосовано через transactional ledger та advisory lock, наявний профіль збережено. Інтерфейс містить список, створення чернетки, додавання/редагування/видалення витрат, серверний підсумок і явне відновлення після конфлікту без мовчазного видалення тексту форми.

`npm run migrate`, `npm run typecheck`, `npm run build` і `npm test` пройшли. Три інтеграційні тести з реальним emulator/PostgreSQL охоплюють профіль і два власники, чужу справу 404, однаковий ключ конкурентно, різні ключі з однаковою revision, повтор ключа з іншою командою, дрібні копійки, дробові копійки й переповнення. Build попереджає про chunk >500 kB. Browser review координатора триває. Враховано зауваження часткового reviewer: no-store, очікування list до створення, збереження ключа при невизначеній server/network помилці.
