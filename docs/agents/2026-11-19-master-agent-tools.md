Нативний цикл зберігає повні model parts, сигнатури й ID, обмежує виклики чотирма раундами, перевіряє Zod-аргументи та вимагає пошук і повтор для слабкого результату. Дані справи й власник беруться із серверного контексту. Обидва роутери підтримують NativeAgent та існуючий test responder; production wiring координатор має передавати native або null (503). Історія до 10 обмінів, user/model; вкладені гранти і пропозиції зберігаються у payload. Події lifecycle можна передати через `res.locals.agentProgress`. SSE-обгортка ще не реалізована.

Пропозиції зберігаються до явного POST-підтвердження. Apply перевіряє власника, оплату, ревізію справи й профілю, строгий тип та ключ повтору. Фінансові припущення за схемою `FinancialAssumptionsSchema` зберігаються окремо в `cases.details.financialAssumptions`, не змінюють чинний фінплан і не є перевіреним розрахунком. Детермінований фінансовий валідатор наразі повертає unavailable; реалізація етапу 4. Перевірка чутливих запитів — обмежена евристика, не гарантія; потрібна незалежна перевірка. Стан пропозиції у старому payload історії не гідратується після застосування, тому UI повинен покладатися на актуальний статус із сервера або оновити інтеграцію.
