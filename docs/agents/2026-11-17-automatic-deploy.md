# Автоматичний деплой з GitHub

- Виконавець: Codex. Гілка `codex/automatic-cloud-run-deploy`, base `cd1fd12` із підтвердженого `origin/main`.
- Межі: автоматизувати реліз сайту після push у main. Власні файли: GitHub workflow, Docker ignore, два скрипти, інструкція і звіти.

У Google Cloud не було підключень або тригерів Cloud Build. Реліз додано до чинного GitHub Actions після інтеграційних тестів. Авторизація використовує Workload Identity Federation, обмежену числовими ID GitHub власника й репозиторію, конкретним workflow, гілкою main і подіями push та workflow_dispatch. Збірка використовує той самий Dockerfile, публічну конфігурацію Firebase Web App і наявний Artifact Registry.

Підготовлено сценарій налаштування IAM із власним deployer акаунтом. Він може оновлювати лише вибраний вебсервіс і завдання міграції та запускати останнє. Реліз перевіряє актуальний GitHub main перед зміною production, запускає міграції через наявний Cloud Run job і перемикає трафік на готову ревізію. За збоєм HTTPS health відновлює попередній розподіл трафіку. Каталогові jobs не входять у цей workflow.

Перевірено синтаксис Bash і YAML, чистоту diff та захист від запуску поза workflow. Імітація CLI підтвердила успішний реліз, пропуск неактуального коміту, зупинку після помилки міграції та повернення трафіку після невдалого health check.

Реалізація на GitHub у [PR №13](https://github.com/stashnid/GrantFolio/pull/13). Автоматична перевірка відхилила запуск сценарію IAM без явного підтвердження постійних прав `grantfolio-deployer` на registry, Cloud Run та використання `grantfolio-runtime`. Перший хмарний запуск і IAM залишаються відкритими. Після підтвердження виконати [інструкцію запуску](../../infra/README.md) та перевірити Actions і публічний health.
