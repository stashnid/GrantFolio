## Рішення й реалізація

- Правила зберігаються за програмою й редакцією. Для «Власної справи» є умови старту й масштабування, для «Гранту на сад» окремі блоки щодо землі, культури, зрошення та підписаного проєкту. Заповнені відомості профілю можуть підставлятися як пропозиції. Заявник зберігає своє підтвердження.
- Питання обираються правилами. Суми кошторису, запиту й власного внеску звіряються в копійках. У формі показано, що потрібно виправити або уточнити. API обмежує доступ власником, відхиляє застаріле збереження і скидає підтвердження після зміни проєкту або анкети.
- Постанова №1214 вимагає відповідної пари XLSX і PDF для електронного бізнес-плану «Власної справи». Дія містить посилання на приклад і канал подання. Для саду потрібна сканована копія підписаного розробником проєкту висадки, якого застосунок не формує. [Вимоги, зіставлення й план випуску](../grant-application-workflow.md)

## Перевірки й передача

- Локальна міграція 017, `npm run typecheck`, `npm run build`, `git diff --check`, 110/110 тестів на інтегрованому `main`. Тести перевіряють кошторис до копійки, специфічні обмеження, доступ двох власників, 409 при одночасному записі, скидання підтвердження та видалення разом з проєктом. Два попередні тести каталогу залежали від дати завершення перевірки прийому. У тестах зафіксовано день сценарію.
- Chromium з Firebase Auth Emulator і окремою локальною PostgreSQL. Для «Власної справи» підтверджено збереження напряму «масштабування» і статусу ФОП, перехід до локації та запитання про тривалість діяльності. Для «Гранту на сад» після перезавантаження перевірено збережені відповіді, зауваження щодо площі й строку користування та вимогу підписаного проєкту.
- Автоматична генерація файлів встановленої форми, помісячний фінансовий план і анкети решти програм залишаються в плані. Перевірки виконано локально на синтетичних даних. Публічне розгортання не виконувалось.
