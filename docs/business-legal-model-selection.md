# Модель для бізнес-кейсів, юридичних умов і пошуку грантів

Дата дослідження: 13.11.2026. Статус: вибір кандидатів за документацією та дослідженнями, без власного benchmark або платних викликів. Ідея користувача про Opus розглядається як гіпотеза, не як наказ оголосити переможця.

## Рекомендація

Для першого якісного прототипу пропоную **Opus 5.5 як основного кандидата для складного розбору бізнесу, зіставлення умов і дослідження джерел**. Одна модель на цьому етапі спростить перевірку. Попередня рекомендація Sonnet була орієнтована на доступність і вартість; вона не доводила його достатності для юридично складних кейсів. Sonnet залишається обов’язковим контрольним кандидатом.

Це інженерна рекомендація, а не висновок «Opus найкраще знає українське право». Перевірені джерела не встановлюють переможця на актуальних українських грантах. Поки немає власних результатів, не вводимо автоматичне розділення на дешеву/дорогу модель лише за назвою задачі.

## Кандидати

| Модель | Навіщо перевіряти | Обмеження висновку |
|---|---|---|
| Claude Opus 5.5 | Основний кандидат: тривала робота з кейсом, суперечності, винятки, цілісний план | Загальні здібності не доводять правильність грантової eligibility |
| Claude Sonnet 5.5 | Контроль: чи дає практично той самий результат швидше/дешевше | Не відкидати через нижчу ціну; не припускати рівну якість без тесту |
| Claude Fable 5.2 | Додатковий кандидат для найскладніших досліджень | Провайдер позиціонує для demanding reasoning; дорожчий, перевагу на наших кейсах не виміряно |
| Gemini 4 Carbon | Початковий незалежний від Anthropic контроль, Google Cloud та пошукові інструменти | Наявність пошукових можливостей не гарантує правильного читання норм; фактичний доступ перевіряється |
| GPT-6 Astra API | Додатковий контроль складного reasoning/research при погодженому бюджеті | Окремий доступ і API-бюджет; вибір Astra в Codex не дає автоматично API продукту |

Первинні model cards: [Opus](https://platform.claude.com/docs/en/models/opus-5-5/overview), [Sonnet](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [Fable](https://platform.claude.com/docs/en/models/fable-5-2/overview), [Carbon](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/4-carbon), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra).

Opus/Sonnet/Fable мають документований доступ через обидва варіанти Claude у GCP; доступ конкретного проєкту ще не перевірений. Основний shortlist: **Opus + Sonnet + Carbon**. Fable/Astra додаються лише якщо залишилися складні невирішені сценарії, щоб не оплачувати безмежний турнір моделей.

## Що означає сильна бізнес-юридична база

Модель має правильно розкласти бізнес-потребу на мету, обмеження й альтернативи; перевірити юридичну форму, регіон, допустимі витрати, співфінансування, строки та зобов’язання; знайти відсутні факти; пояснити причинний зв’язок і показати точний доказ кожного суттєвого висновку.

Обсяг навчального корпусу українського права й гарантовану актуальність знань цих моделей перевірити за відкритими картками не можна. Тому рішення спирається на **модель + актуальні джерела + перевірка**, а не на декларацію про сильну внутрішню базу.

Для кожного висновку зберігаємо: критерій → факт бізнесу → джерело і точний фрагмент → дата/редакція → відповідає/не відповідає/невідомо → наступна дія. Прогноз успішності заявки відокремлюється від формального права податися. Не вигадуємо відсоток отримання гранту.

## Що кажуть дослідження, а чого вони не доводять

- [LegalBench](https://arxiv.org/abs/2308.11462) охоплює різні юридичні задачі, але переважно англомовне американське право; його результати не є рейтингом українських грантових консультантів.
- [FinanceBench](https://arxiv.org/abs/2311.11944) перевіряє фінансові відповіді з доказами у звітності. Корисний принцип — правильна відповідь разом із підтверджувальним уривком. Це не тест стратегічної поради малому бізнесу чи поточних конкурсів.
- [UA-Legal-Bench](https://arxiv.org/abs/2605.29170) є українським preprint: п’ять задач на судових рішеннях. Він показує залежність результату від задачі й небезпеку простого accuracy при нерівномірних класах. Прямого порівняння актуальних Opus/Sonnet для грантів немає.
- [Multi-Legal-Bench v3](https://arxiv.org/abs/2605.29738v3) виправляє попередні результати та демонструє вплив підказок-відповідей у тексті. Старий пошуковий snippet може переказувати попередню версію. Це причина перевіряти версію роботи та якість тесту; стійкість Sonnet 5 до masking не встановлює його перевагу над Opus на наших кейсах.
- [Дослідження юридичних RAG-систем](https://dho.stanford.edu/wp-content/uploads/Legal_RAG_Hallucinations.pdf) показує, що наявність retrieval/citations не усуває помилкових юридичних відповідей. Перевіряти потрібно, чи саме наведений уривок підтримує конкретний висновок.

Загальні тести coding/math або маркетингові claims не перетворюємо на юридичний рейтинг. Власного порівняння ще не проводили.

## Пошук грантів — окремий шар

Модель не знаходить нові конкурси лише завдяки своїм вагам. Потрібні API search, завантаження/читання першоджерел, обробка PDF та перевірка редакцій. Пошуковий snippet — лише вказівка, остаточний висновок потребує відкритого документа.

Порядок джерел: чинне оголошення й офіційні зміни грантодавця; релевантний чинний нормативний акт і дата набрання чинності; офіційні FAQ/роз’яснення. Перекази й агрегатори — для discovery. При суперечності між правилом і FAQ не обирати зручний текст; показати конфлікт для перевірки. FAQ не може мовчки змінити закон чи формальні умови.

Pipeline: бізнес-профіль → кілька цільових пошукових запитів → офіційні сторінки → дедуплікація програм/раундів → перевірка дедлайну й стану → таблиця критеріїв → короткий список з причинами й невідомими фактами. Повний каталог і універсальну повноту вебпошуку не обіцяємо.

[Claude web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool) доступний як окремий tool із обмеженнями використання/доменів. [Web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool) має окрему матрицю платформ; Google-managed не слід вважати ідентичним Anthropic-managed. Для конкретного endpoint перевіряємо обидві можливості; за потреби backend виконує дозволене завантаження й передає текст. Функція Research у готовому чат-застосунку не дорівнює автоматично доступному API workflow.

## Вартість Opus у контексті рішення

На дату перевірки базові direct API input/output тарифи за 1 млн токенів: Sonnet $2/$10, Opus $4/$20, Fable $8/$40. Це не повна ціна справи: окремо враховуються thinking output, повторні turn, пошук, прочитані документи й регіональні тарифи. [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing).

Власний приклад при однакових 30K input і 5K оплачуваних output: Sonnet $0.11, Opus $0.22, Fable $0.44. Реальна кількість токенів відрізнятиметься. Подвоєння тарифу не означає, що дослідження обов’язково коштує рівно вдвічі більше. Для кількох тестових кейсів варто спершу виміряти якість Opus, а не відхиляти його лише через ціну. Конкретний ліміт витрат погоджується перед запуском.

## Як визначимо переможця

Підготувати 24 перевірені українські бізнес-кейси, по 4 на групу:

1. Чітка відповідність і очевидна невідповідність.
2. Юридична форма/територія/статус заявника та винятки.
3. Витрати, внесок, бюджет і зобов’язання.
4. Відсутні або суперечливі факти бізнесу.
5. Змінені умови, прострочений конкурс, конфлікт джерел.
6. Підбір серед кількох програм і обґрунтування бізнес-доцільності.

**Фаза A: міркування.** Ті самі заморожені документи, дата оцінки, схема відповіді, task instructions і допустимі інструменти для трьох моделей. Зафіксувати окремі provider-specific effort settings; однакове слово high не означає однаковий compute. До 72 первинних відповідей; без автоматичних безмежних повторів.

**Фаза B: пошук.** На невеликій частині тих самих кейсів — однакові пошукові можливості, час і ліміт відкритих сторінок. Reference list готує людина; coverage вимірюємо лише відносно нього, не як частку всіх грантів інтернету. Окремо порівнюємо повноту пошуку й правильність читання знайденого. Нативні tool stacks можна оцінити додатково як продуктову систему, не змішувати їх із чистим рейтингом моделей.

Відповіді анонімізуються для оцінювачів. Команда перевіряє структуру/числа; спірні юридичні критерії оцінює людина з українською юридичною або грантовою компетенцією. Якщо такої перевірки немає, результат називаємо внутрішнім технічним пілотом, не юридично валідованим benchmark.

Для кожного кейсу записуємо: правильність критеріїв, підтвердження кожного суттєвого твердження точним джерелом, актуальність, уточнення unknown, практичність поради, українську мову, latency, tokens, tool calls і ціну. Окремо критичні помилки: вигадана норма/джерело, неправильна eligibility, пропущений дедлайн/зобов’язання, змішана юрисдикція, витік даних. Середня хороша оцінка не перекриває критичну помилку.

Рішення: Opus лишається основним, якщо його перевага в складних кейсах виправдовує ціну/час. Якщо Sonnet проходить ті самі критерії, дешевші сценарії можна перевести на нього. Fable/Astra перевіряємо на невирішених кейсах, а не призначаємо переможцями наперед. Тести не є додатковим академічним deliverable; це внутрішнє обґрунтування вибору продукту.

## Зв’язок із навчанням і розробкою

Цей етап передує підготовці SFT: спершу з’ясовуємо, чи проблема у міркуванні, пошуку, даних або prompt. Ваги Claude не донавчаємо через недоступний стандартний API. Нові правила/дедлайни оновлюються у джерелах, а не запам’ятовуються SFT.

Astra координував дослідження; Sol перевіряв Anthropic, Terra — юридичні benchmark і дизайн оцінювання. Це моделі розробки в Codex; модель продукту обирається окремо. Платних запитів, користувацького тестування та навчання не проводили.

## Конкретні порівняння провайдера

У [Sonnet announcement](https://www.anthropic.com/claude-sonnet-5-5) GDPval-AA: Sonnet 1844, Opus 1846; AA-Briefcase: 1811 проти 1822. Ці близькі результати не доводять універсальної переваги Opus. Anthropic окремо відзначає Opus для тривалих відкритих задач із sustained judgment; це оцінка провайдера, не український грантовий тест.

У [Fable announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2) WANDR search: Fable 82.1% проти Opus 72.3%; AutomationBench 51.4% проти 42.5%. При цьому результати різних метрик Briefcase не дають однакового порядку моделей. Налаштування effort і версія прогону важливі; не змішуємо цифри різних публікацій у єдиний рейтинг. Ці дані обґрунтовують включення Fable до складних контрольних кейсів, але не обов’язкову покупку найдорожчої моделі.

Для якісного незалежного контролю обрано Carbon замість дешевшого Argon: у наведеній Anthropic-оцінці Carbon показує сильний AutomationBench, хоча це не Google-незалежна оцінка грантів. Argon можна додати згодом як цінову альтернативу. Не прирівнювати бізнес-автоматизацію до юридичної достовірності.
