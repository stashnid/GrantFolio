# Спільна робота через Codex

Рішення користувача, 13.11.2026: Astra координує роботу; окремі задачі делегує агентам інших моделей. Обидва учасники працюють у Codex.

| Роль | Модель за замовчуванням | Обов’язок |
|---|---|---|
| Координатор | Astra | Ціль, межі задач, залежності, рішення, інтеграція й перевірка результату |
| Дослідження | Sol | Першоджерела, альтернативи, ціни/обмеження з датою перевірки |
| Реалізація | Terra | Обмежена ділянка коду, необхідні тести, звіт про зміни |
| Незалежна перевірка | Sol або Terra, інший агент | Перевірка конкретного diff і критеріїв приймання |

Це робочий розподіл, не виміряний рейтинг моделей. Координатор обирає доступну модель під задачу й записує фактичний вибір. Якщо модель/агент недоступні, чесно фіксує fallback; не називає власну перевірку незалежним review.

## Цикл задачі

1. Кожний Codex перевіряє локальний стан і свіжий GitHub, читає AGENTS/STATUS. Спільного автоматичного доступу до пам’яті двох чатів немає.
2. Astra задає task ID, результат, критерії приймання, base SHA, залежності й конкретні файли агента. Передає тільки потрібні документи та контракти.
3. Незалежні задачі виконуються паралельно, залежні — після погодження контракту. Зазвичай достатньо двох виконавців; не запускати агента на кожну дрібну правку.
4. Для коду — окрема гілка/worktree на задачу. Не дозволяти двом агентам одночасно змінювати той самий файл. STATUS/DECISIONS інтегрує координатор; виконавці пишуть окремі звіти.
5. Звіт містить фактичні модель/роль, base SHA, зроблене, перевірки, невідоме й наступний крок. Переривання теж фіксується.
6. Astra читає diff і результати, перевіряє взаємодію частин. Автор не є єдиним reviewer для змін доступу, бюджету чи даних.
7. Перед PR — fresh fetch, безпечне узгодження upstream, потрібні перевірки, оновлення контексту. Публікація/merge лише в дозволеному користувачем обсязі; без force push.

Початковий пакет: [AGENTS](../AGENTS.md), [STATUS](STATUS.md), [BACKLOG](BACKLOG.md), [шаблон звіту](agents/TEMPLATE.md). Зміни поведінки моделей і ціни перевіряються заново перед використанням.

## Контроль витрат

Спочатку коротка задача одному виконавцю; додатковий агент потрібний для незалежної перевірки або окремої паралельної роботи. Не дублювати однаковий research і не передавати весь чат кожному агенту. Astra залишається відповідальною за рішення, а не переписує без перевірки відповіді виконавців.

Ці агенти допомагають створювати продукт. Асистент підприємця всередині GrantFolio має окремий API, модель і бюджет; вибір Astra в Codex не визначає модель продукту.
