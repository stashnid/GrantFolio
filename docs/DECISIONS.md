# Журнал рішень

Дата всіх початкових записів: 12 листопада 2026. «Прийнято користувачем» і «рекомендація» мають різний статус. Зміни додаємо новим записом із посиланням на попередній.

| ID | Рішення | Статус і підстава |
|---|---|---|
| D01 | Розгортати в Google Cloud | Прийнято користувачем. Замінює Render/Supabase та варіант AWS як поточний deployment |
| D02 | Зберігати контекст, хід робіт агентів і передачу задач у GitHub | Вимога користувача. AGENTS → STATUS → актуальні плани → звіти/WORKLOG |
| D03 | Одна TypeScript кодова база, модульний сервер, React | Інженерна рекомендація. Менше інтеграцій для двох учасників; окремі entrypoint для web/worker/jobs |
| D04 | Cloud Run, Firebase Auth, Cloud SQL PostgreSQL, приватне Storage, Tasks/Scheduler | Поточний план під Google Cloud. Ресурси ще не створено |
| D05 | Власник перевіряється на backend; DB доступна лише серверу | Рекомендація. Не вводимо власну складну RLS-схему на старті; UID Firebase зберігаємо як TEXT |
| D06 | Формули бюджету в коді, факти з джерел і підтвердження користувача | Продуктова вимога узгодженості. ШІ пропонує тексти/зміни; суми й права доступу перевіряє сервер |
| D07 | `gemini-3.5-flash-lite` як перший кандидат, з можливістю managed SFT | Попередній вибір за можливостями/вартістю. Потрібні перевірка акаунта і якість українською; альтернативи — у дослідженні |
| D08 | Спочатку зібрати дозволені, перевірені приклади; потім справжнє донавчання й порівняння | Матеріалів немає, відповідь користувача. Prompt/retrieval не називаємо донавчанням |
| D09 | OOAD лише як рекомендації | Пряме уточнення користувача. Покажчик матеріалів не потрібний для відновлення контексту |
| D10 | Пріоритет до 19.11 — вимоги завдання та один завершений корисний сценарій | Вимоги викладача + README. Моніторинг розширюємо поступово; платіж — необов'язковий бонус |
| D11 | Не припускати покриття AI за самим фактом наявності кредитів | Потребує перевірки точного billing/credit entitlement. Не змінюємо billing і не запускаємо платні роботи в межах планування |
| D12 | Подальша командна розробка через окремі гілки/PR з актуальним handoff | Рекомендація спільної роботи. Початкову документацію можна синхронізувати в main у межах поточного запиту |

Історичні звіти можуть містити інші рекомендації. Поточні рішення тут і в [архітектурі](architecture.md) мають пріоритет; фактичний стан — у [STATUS](STATUS.md).

## Уточнення 13.11.2026

- D13 (вимога користувача): Astra координує; Sol/Terra виконують обмежені задачі. Обидва учасники працюють у Codex.
- D14 (рекомендація, уточнює D07): перевірити Claude Sonnet 5.5 для основного письма; Gemini лишається контролем/варіантом SFT. Доступне self-serve донавчання ваг Claude не підтверджене. [План](anthropic-assistant-plan.md).

- D15 (рекомендація, уточнює D14): Opus-first пілот для складних кейсів; не оголошувати Opus найкращим юридичним ШІ без доказів. Порівняння з Sonnet/Carbon, Fable/Astra — додаткові кандидати. [Обґрунтування](business-legal-model-selection.md). Ідея користувача про Opus не є остаточним рішенням моделі.

- D16 (пропозиція): спочатку вертикальні зрізи auth → case/budget → AI/export → користувачі. Першим адаптером розглянути оновлену Власну справу; актуальний набір не підтверджено. [Дослідження виконання](next-work-research.md). Скорочення demo scope потребує окремого рішення команди.
