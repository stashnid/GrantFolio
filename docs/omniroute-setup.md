# OmniRoute для розробки через Codex

Оновлено 15.11.2026. Цей документ замінює попередню інструкцію інтеграції в асистента GrantFolio: користувач уточнив, що шлюз потрібен для розробки в Codex.

OmniRoute видалено з runtime-залежностей застосунку, серверного адаптера, `.env.example` та `scripts/dev-local.sh`. Продуктовий асистент після цього отримав окрему пряму інтеграцію Gemini (див. README), без залежності від OmniRoute. Без серверного ключа він повертає 503; історія та інші функції збережені.

## На цьому Mac

Шлюз і приватні дані перенесено за межі GrantFolio у `~/.codex/omniroute/`. Провайдера `omniroute` зареєстровано в приватному `~/.codex/config.toml`, типовою моделлю встановлено `codex-free`. Попередню конфігурацію збережено у `~/.codex/config.before-omniroute-20261114.toml` (також приватна). Ключі не копіювати в Git.

Фоновий сервіс `com.stashnidyk.codex-omniroute` запускається при вході користувача на Mac та слухає лише `127.0.0.1:20128`. Команда `~/.local/bin/codex-free` перевіряє готовність шлюзу й запускає Codex CLI через нього. Для розробки:

```sh
cd ~/Desktop/GrantFolio
~/.local/bin/codex-free
```

Для нового desktop-сеансу потрібно перезапустити Codex, щоб він перечитав конфігурацію. Поточний відкритий чат та його запущені вбудовані агенти автоматично не перенесені на іншого провайдера. CLI-перевірка не підтверджує, що конкретний існуючий desktop-чат змінив провайдера; перевіряти обраний провайдер/модель та факт запитів у шлюзі.

Маршрут `codex-free`: Gemini 3.5 Flash-Lite → Groq GPT-OSS 120B; priority, без платного резерву, без локальних моделей. OpenRouter та Claude не підключені. Вичерпання всіх квот усе одно зупиняє роботу. Великий контекст може не вміщатися в безкоштовний TPM Groq; на реальному Codex-запиті отримано 413 (8 000 TPM, запит 11 334). Сам факт успішного короткого API-запиту не доводить придатності резерву для великого сеансу розробки.

## Перевірка

Codex CLI через OmniRoute прочитав `sum.mjs`, виправив віднімання на додавання та виконав Node-перевірки двох випадків. Повторний запуск прочитав виправлений файл. Це були окремі CLI-сеанси через Gemini, а не вбудовані агенти desktop-чату. Після скорочення допоміжного контексту CLI короткий запит Codex пройшов через Groq: `FALLBACK_OK`, лог шлюзу підтвердив 1 fallback і 200. Перший target було тимчасово замінено на модель із квотою 0, після тесту відновлено Flash-Lite. Це не перевірка тривалого coding-сеансу на Groq. Легкий launcher вимикає зайві MCP/Apps, вкладених агентів, web search, image/sleep tools і скорочує каталог навичок; основні інструменти читання/редагування/запуску залишаються. Повний desktop-сеанс може мати значно більший контекст.

Налаштування провайдерів є локальними для цього Mac. Другові потрібне власне встановлення й власні дозволені доступи. [Документація конфігурації Codex](https://developers.openai.com/codex/config-advanced/) і [ліміти Groq](https://console.groq.com/docs/rate-limits).
