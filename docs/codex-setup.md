# Codex для обох учасників GrantFolio

Спільні правила зберігаються в [AGENTS.md](../AGENTS.md), а не в пам’яті окремого чату. Обидва учасники відкривають у Codex корінь свого клону GrantFolio. Не потрібно копіювати чужий глобальний AGENTS.md або ~/.codex: там можуть бути особисті налаштування й доступи.

## Отримати ці інструкції

Поки цей пакет не злитий у головну гілку, він доступний у `chore/ecc-development-routing`. У чистому клоні:

```bash
git status --short --branch
git fetch origin
git switch --track origin/chore/ecc-development-routing
```

Якщо локальна гілка з цією назвою вже існує, використати `git switch chore/ecc-development-routing`, потім `git pull --ff-only`. За наявності незбережених змін або розходження історії спочатку зберегти й розібрати їх; не використовувати reset, force push або примусове перемикання. Після злиття достатньо оновити main. Робочі задачі створювати в окремих гілках від погодженої командою актуальної бази.

## Один раз на кожному комп’ютері

Git переносить інструкції, але не встановлені плагіни, акаунти чи довіру до hooks. Кожен учасник налаштовує власний Codex. Перевірена локальна конфігурація першого учасника: Codex CLI 0.163.0, ECC 2.2.3; це не підтвердження встановлення на комп’ютері друга.

### ECC: розробка та технічні перевірки

Потрібний Codex із підтримкою `plugin marketplace add` і `plugin add`, Git та Node.js для вбудованих допоміжних скриптів. Якщо цих підкоманд немає, оновити Codex офіційним способом, а не замінювати інсталяцію старим sync-скриптом.

Перевірити поточний стан:

```bash
codex --version
codex plugin list --json
```

Якщо ECC ще відсутній, встановити з того самого перевіреного commit:

```bash
codex plugin marketplace add affaan-m/ECC --ref d2ef2680594f9a17526a6e1a2e18b3d242c5d17b
codex plugin add ecc@ecc
codex plugin list --json
```

Очікуваний запис: `ecc@ecc`, `version: 2.2.3`, `installed: true`, `enabled: true`. Якщо ECC вже встановлений, спочатку порівняти версію та джерело; не накладати legacy sync або ручне копіювання skills поверх нативного плагіна. Commit зафіксовано для однакового старту; майбутнє оновлення потребує перевірки нового upstream та зміни ref, а не припущення, що pinned marketplace завжди слідує main.

Перезапустити Codex. У новому чаті попросити прочитати конкретну навичку, наприклад `api-design` або `backend-patterns`, і назвати її фактичне джерело. Сам запис у списку плагінів не доводить, що навички завантажилися в поточний чат.

На першому комп’ютері додатково пройшов офіційний `scripts/codex/check-plugin-cache.js` з явно вказаним активним кешем. Він перевіряє посилання manifest на skills, hooks, MCP та assets, а не виконання всіх навичок. За проблем із завантаженням використати [офіційні примітки Codex](https://github.com/affaan-m/ECC/blob/d2ef2680594f9a17526a6e1a2e18b3d242c5d17b/.codex-plugin/README.md).

### gstack: планування, дизайн, інтегроване QA й реліз

Якщо навички gstack вже доступні в Codex, повторно встановлювати їх не потрібно. Перевірити наявну інсталяцію та її версію. Для нового встановлення потрібні Git, Bun та інші залежності з [офіційної інструкції](https://github.com/garrytan/gstack#other-ai-agents). На macOS/Linux або в підготовленому WSL, якщо директорія призначення ще не існує:

```bash
mkdir -p ~/codex-tools
git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/codex-tools/gstack
cd ~/codex-tools/gstack
./setup --host codex
./setup --status
```

Перед виконанням setup переглянути отриману документацію й версію; не перезаписувати наявну інсталяцію. Для native Windows користуватися актуальним Windows-порядком із документації gstack, не запускати наведені shell-команди як PowerShell-команди. Перезапустити Codex і перевірити, що він знаходить `gstack-qa` та `gstack-design-review`.

Підтримка gstack у Codex позначена upstream як experimental; частина захисних правил є рекомендаціями, а не примусовими блокуваннями. Окремі зовнішні рев’ю потребують власної інсталяції та входу в Claude Code CLI. Якщо її немає, записати обмеження, не стверджувати, що зовнішнє рев’ю відбулося.

### Принципи Karpathy

Окремий плагін не потрібний: правила вже записані в AGENTS.md. Уточнювати істотні припущення, робити найпростіше достатнє рішення, змінювати лише потрібне та перевіряти конкретний результат.

## Які навички обирати

| Завдання | Основний набір |
|---|---|
| React/TypeScript та Express, API, PostgreSQL, міграції | ECC: coding-standards, frontend-patterns, backend-patterns, api-design, postgres-patterns, database-migrations |
| Необхідні тести, діагностика збірки, локальне code/security review | ECC: tdd-workflow, verification-loop, security-review і відповідні стеку навички |
| Нове планування та перегляд дизайну | gstack: office-hours/autoplan/design-review за потребою; не переплановувати погоджене автоматично |
| Перевірка готового користувацького сценарію | gstack: qa; для звіту без виправлень — qa-only |
| Підготовка PR, реліз, deployment | gstack у явно дозволеному обсязі; платні ресурси потребують окремо погодженого бюджету |

Завантажувати лише потрібні SKILL.md, не всі 314 навичок у контекст. Один інструмент відповідає за конкретну перевірку; повторне еквівалентне рев’ю без причини не потрібне. Налаштування інструментів не змінює вимог викладача, Google Cloud, правил доступу чи погодженого продуктового плану.

## Кожна робоча сесія

1. Перевірити локальні зміни та свіжий origin. Прочитати AGENTS → STATUS → DECISIONS → BACKLOG і останній handoff; для коду — актуальну архітектуру.
2. Узгодити з другим учасником task ID, базову гілку та файли. Не дозволяти двом Codex одночасно змінювати ті самі файли.
3. Створити task branch і короткий звіт у docs/agents. Виконувати одну обмежену задачу через відповідний набір навичок.
4. Перевірити критерії приймання, записати фактичні результати й наступний крок. Оновити STATUS/WORKLOG і передати PR на перевірку.

Власні логіни, секрети та доступи налаштовуються окремо. Не переносити чужі токени, browser sessions або ~/.codex у Git. Hook trust переглядається штатними засобами Codex; інструкції не надають автоматичної довіри hooks і не запускають continuous learning чи додаткові MCP. Плагін ECC постачає власний MCP і SessionStart hook; їхня наявність не є доказом запуску або повного функціонального паритету з Claude Code.

```text
Прочитай AGENTS.md і docs/codex-setup.md. Перевір локальний Git та свіжий origin, потім прочитай STATUS, DECISIONS, BACKLOG і останню передачу роботи. Перевір доступність потрібних ECC/gstack skills, назви знайдені джерела та обмеження. Дотримуйся спільного розподілу інструментів і погодженого плану. Поки не призначено задачу та власні файли, не починай реалізацію.
```
