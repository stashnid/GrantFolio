## Підтримка входу через Google на мобільних пристроях (Redirect Flow та In-App Browser Guidance) — 18.11.2026

1. **Діагностика проблеми входу через Google на телефонах**:
   - `signInWithPopup` на мобільних браузерах (iOS Safari, Android Chrome) блокується вбудованими блокувальниками спливних вікон за замовчуванням (`auth/popup-blocked`).
   - Якщо вікно відкривалося як нова вкладка в iOS Safari, переведення головної вкладки у фон заморожувало виконання скриптів, а після закриття вкладки авторизації поверталася помилка `auth/popup-closed-by-user`, через що стан входу не зберігався.
   - У вбудованих браузерах месенджерів (Telegram Webview, Instagram, Facebook) Google OAuth заблоковано на рівні політик Google (`403: disallowed_useragent`), а `window.open` заблоковано Webview.
2. **Впровадження адаптивної моделі авторизації (`frontend/src/App.tsx`, `frontend/src/workspace.css`)**:
   - Для мобільних телефонів (`isMobileDevice()`) замість спливних вікон впроваджено офіційний стандарт Firebase **`signInWithRedirect`**: браузер переходить на сторінку Google у поточній вкладці без блокувань та спливних вікон, а після входу повертається на GrantFolio.
   - Додано обробник відновлення результату перенаправлення `getRedirectResult(auth)` на старті застосунку (`useEffect`).
   - На десктопах збережено швидкий `signInWithPopup`, а в разі блокування спливного вікна браузером система автоматично переходить на безпечний `signInWithRedirect`.
   - Додано детектор вбудованих браузерів (`detectInAppBrowser()`) та підказку `.auth-inapp-notice` з чіткою інструкцією: відкрити в системному Safari / Chrome (меню ⋯) або увійти за поштою та паролем.
3. **Верифікація**:
   - `npm run typecheck`, `npm run build` — 0 помилок. Юніт-тести бекенду пройдено.
